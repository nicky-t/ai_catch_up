# 053 ベンダー・ツール選定：自社開発 / SaaS / プラットフォームの比較軸

!!! abstract "この記事で説明できるようになること"
    - 「自社開発（Build）」「購入（Buy）」「併用（Hybrid）」を決める比較軸をチェックリストとして説明できる
    - 自社開発・購入それぞれで見落とされがちなコストを具体的に挙げられる

## 仕組み

判断の前に、対象を3つの軸で分類する（出典: Stack AI「Build vs Buy for Enterprise AI」2026年版フレームワーク）。

- **データの性質**：正式な業務データを更新する「system of record」／分析・判断支援の「system of intelligence」／社員・顧客との対話の「system of engagement」
- **影響範囲**：社内生産性向け・顧客向け・規制対象の意思決定のどれか
- **段階**：要件を探る「build-to-learn」（期間・影響範囲を小さく区切る）か、本番運用の「build-to-run」（SLA・監査・変更承認が必要）か

分類したうえで、次の6ステップで進める。

1. 業務成果（処理時間短縮・解決速度など）と「誤りのコスト」を数値で置く
2. データ分類・所在地・保持期間・SSO・RBAC・監査ログなど制約を洗い出す
3. 差別化につながる部分（独自ポリシーロジック・固有連携・評価基盤）は自社保有、汎用部分（標準コネクタ・RAG基盤・監視ダッシュボード）は外部調達に分ける
4. 評価ハーネス・品質・コスト・遅延の継続監視・インシデント対応など運用体制を確認する
5. 2〜4週間、1つの業務フロー・1つの難しい連携・1つのKPIで検証する
6. 重み付きスコアカード・提言メモ・セキュリティ承認計画をそろえて判断する

## 比較・判断基準

10項目を1〜5点で採点し重みを掛ける「重み付きスコアカード」が核になる。

| 項目 | Buyが有利になりやすい場合 | Buildが有利になりやすい場合 |
|---|---|---|
| 差別化・競争優位 | 機能が容易に模倣される | AIが製品の中核 |
| データ優位性 | 独自データが少ない | 独自データと改善ループがある |
| 導入の緊急度 | 90日以内に効果が必要 | 反復開発の時間がある |
| 連携の複雑さ | 幅広いコネクタが必要 | 自社に連携基盤のノウハウがある |
| コンプライアンス負荷 | 監査対応機能が既にある | 全要素を統制できる体制がある |
| 人材の余力 | 既存チームが手一杯 | 専任の基盤チームがある |
| コストの予測可能性 | 利用量の上限管理が組み込まれている | モデルルーティング等を自前最適化できる |
| ロックイン・撤退戦略 | 契約上の緩和策で足りる | 高い移植性が必要 |
| 性能・遅延要件 | 中程度の遅延で許容される | 低遅延の深い最適化が必要 |
| 変更管理の難易度 | 既製のUI・導入形態でよい | 社内UI基準を統一できる |

規制業界（銀行・医療・保険）はコンプライアンスとデータ統制を「very high」に重み付けし、顧客向けエージェントは安全性と評価成熟度を重く見る、といった具合にシナリオ別に重みを変える。

## 落とし穴

1. **TCO（総保有コスト）の見落とし**：自社開発ではデータ同期・回帰テスト・セキュリティレビュー・障害時処理・研修対応のコストが抜けやすい。購入では導入サービス費・従量課金の超過・上位プラン費用・移行コストが見落とされやすい
2. **機能比較だけで決める**：価格表や機能一覧の比較で終わり、監査ログ・権限管理・撤退戦略など運用面の差を見ずに契約してしまう（コストは「座席単価」でなく「成果1件あたりのコスト」で測るべき）
3. **撤退戦略を後回しにする**：ベンダーのロードマップ変更やデータのエクスポート制限を導入後に知る。購入時点で「データ出力・ワークフロー移植・移行想定の契約条件」を先に決めておく必要がある

## 実務への接続

学習051（PoCから本番へ）・052（チェンジマネジメント）で見た「本番化の壁」は、ベンダー選定の時点でも同じ構造で現れる。Gartnerが2028年までに70%が放棄されると予測した「Forward-Deployed」AIエージェント（学習051で紹介）は、まさに「差別化の中核」でないものをBuildしてしまった失敗例として、このスコアカードで説明できる。逆に、損保ジャパンがGemini Enterpriseの標準機能では細かな権限制御ができない部分だけを自前のガードレールで補った事例は、「汎用部分は購入・差別化部分は自社開発」というハイブリッド型の実例になる。

## 講座で使うなら
- 30 秒説明: 「AIツールを入れるとき、『作る』か『買う』かを機能だけで決めると失敗します。差別化になる部分か、誰でも使う汎用部分かで分けて判断する表があります」
- たとえ話: 家を建てるとき、間取りの個性（差別化）は自分で決めるが、配線や水道（汎用部分）は専門業者に任せるのと同じ
- 演習案: 受講者の職場で検討中・導入済みのAIツールを1つ挙げ、10項目のスコアカードのうち3つ（差別化・導入の緊急度・撤退戦略）だけ簡易採点させ、Build/Buy/Hybridのどちらに近いか話し合わせる
