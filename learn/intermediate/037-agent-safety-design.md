# 037 エージェントの安全設計：権限・承認・サンドボックス・監査ログ

!!! abstract "この記事で説明できるようになること"
    - AIエージェントに「何を」「どこまで」任せてよいかを、権限・承認・サンドボックス・監査ログの4層に分けて設計できる
    - 「便利だから許可を広げる」判断が招く典型的な失敗パターンを説明できる

## 仕組み

エージェントの安全設計は、次の4層を組み合わせて考えると整理しやすい。

1. **権限（何をしてよいか）**：ツールごとに「常に許可」「常に拒否」「都度確認」をルールとして定義する。Claude Codeでは、ファイル読み取りのような読み取り専用操作は既定で確認不要、シェルコマンドの実行は原則確認が必要、といった段階（tiered permission system）を持つ
2. **承認（誰が確認するか）**：都度人間が確認する方式に加え、AIエージェントが安全な行動パターンを分類器（classifier）で自動判定し人間の確認を省く「自動モード」もある。確認頻度と作業速度はトレードオフになる
3. **サンドボックス（実行環境の隔離）**：許可ルールはコマンドの「文字列」を見て判断するため、`grep -r`のようにファイル名を直接指定しない操作や、スクリプトが裏でファイルを開く操作はすり抜けうる。OSレベルでファイルシステム・ネットワークアクセスそのものを制限する仕組み（サンドボックス）が、これを補う「多層防御」の役割を持つ
4. **監査ログ（何をしたかを後から追えるか）**：エージェントの行動記録を残し、異常があれば事後に検知・説明できるようにする

権限とサンドボックスは別レイヤーである点が重要：権限ルールがプロンプトインジェクションなどでバイパスされても、OSレベルのサンドボックス制限は独立して機能する。

## 比較・判断基準

| 方式 | 確認頻度 | 向いている場面 |
|---|---|---|
| 都度確認（手動） | 高い | 初導入・本番環境への操作 |
| 自動モード（分類器判定） | 低い | 定型作業・検証済みの繰り返しタスク |
| サンドボックス＋自動化 | 低い（OS側で制限） | 大量エージェントの並列実行 |

「自動化の度合い」と「事故時の被害範囲」は比例する。都度確認から始め、安全性を確認した操作から自動化範囲を広げるのが基本の順序になる。

## 落とし穴

1. **権限ルールだけで安全と思い込む**：文字列マッチのルールは、ファイル名を直接指定しないコマンドやサブプロセス経由の操作をすり抜けることがある。OS側の制限（サンドボックス）と組み合わせないと「すり抜け」を防げない
2. **無関係な設定が機能を静かに無効化する**：Claude Codeでは2026年9月、`AGENTS.md`読み込みがテレメトリー関連の機能フラグに依存する実装になっており、テレメトリーを無効化すると意図せず`AGENTS.md`が読み込まれなくなる不具合が報告された。「プライバシー設定を変えただけのつもりが、別の機能まで止まっていた」という典型例で、設定同士の依存関係を可視化しておく必要性を示す
3. **監査ログを「作るだけ」で見ない**：行動記録があっても定期的にレビューする体制がなければ、異常検知は事後になる。Anthropicが2026年9月23日に公開した事例では、約950体のエージェントが21時間・2.1億トークンを使い新規の酵素システムを発見したが、人間が担当したのは初期プロンプトの作成と実験による検証のみだった。大量エージェントを走らせるほど、「どこまでを機械任せにし、どこで人間が検証するか」という設計判断の比重が増す

## 実務への接続

業務でAIエージェントに定型作業を任せる際は、「一番安全な設定（都度確認・狭い権限）から始め、安全性を確認しながら自動化範囲を広げる」順序を徹底する。特に複数のエージェントを並列で走らせる構成では、個々の権限設定に加え、実行環境そのものの隔離（サンドボックス）と、後から行動を追跡できる仕組みの有無を導入前にチェックリスト化しておくと、事故時の原因調査が早くなる。

## 講座で使うなら

- 30秒説明：「AIエージェントの安全設計は、①何をしてよいか（権限）②誰が確認するか（承認）③実行環境をどこまで隔離するか（サンドボックス）④後から追跡できるか（監査ログ）の4層で考えます」
- たとえ話：新人に仕事を任せるとき、最初は「一つひとつ確認」から始め、信頼できる作業から任せる範囲を広げていく。加えて、机の上（サンドボックス）を区切っておけば、万一の失敗が他の仕事に波及しない
- 演習案：受講者が使っているAIツールで「今どのレベルの確認が必要か」を書き出させ、どの操作なら自動化してよいか・どの操作は都度確認すべきかを議論させる
