# 021 RAGの全体像：検索→生成のパイプラインと失敗ポイント

!!! abstract "この記事で説明できるようになること"
    - RAG（Retrieval-Augmented Generation、検索拡張生成）が何を組み合わせた仕組みかを説明できる
    - 検索→生成のパイプラインを構成要素ごとに説明できる
    - どの段階で失敗が起きやすいかを説明できる

## 仕組み

RAGは、LLMが学習時に内部へ持つ知識（パラメトリックな記憶）だけに頼らず、外部の文書集合から関連箇所を都度検索して回答に使わせる仕組みである。2020年に提案された原論文は、これを「事前学習済みのパラメトリックな記憶と、非パラメトリックな記憶（検索対象の文書索引）を組み合わせて生成する仕組み」と説明している。

パイプラインは大きく4段階に分かれる。

1. **インデックス化**：社内文書などをチャンク（意味のまとまりごとの小さな塊）に分割し、埋め込み（embeddings）に変換してベクトルデータベースに格納する
2. **検索（retrieval）**：ユーザーの質問を同じ埋め込み空間に変換し、意味的に近いチャンクをベクトルデータベースから探す
3. **拡張（augmentation）**：見つかったチャンクを、質問と一緒にプロンプトに埋め込む
4. **生成（generation）**：LLMが、渡されたチャンクを根拠として回答を生成する

原論文はこの構成で、知識集約型のオープンドメイン質問応答タスクにおいて、外部知識を持たないモデルや、検索と抽出を別々に行う従来手法を上回る精度を示したと報告している。ポイントは、LLM自体を再学習させなくても、検索対象の文書を差し替えるだけで知識を更新・追加できる点にある。

## 比較・判断基準

パイプラインのどこに失敗の芽があるかを段階ごとに整理する。

| 段階 | 典型的な失敗 |
|---|---|
| チャンク分割 | 意味のまとまりを無視して機械的に切ると、必要な文脈が別チャンクに分断される |
| 検索 | キーワードが一致しないと類義表現でも見つからない（埋め込みの性質・モデルにより精度差が大きい） |
| 拡張 | 関連チャンクが多すぎて上位に絞れない、または低品質なチャンクが紛れ込む |
| 生成 | 渡されたチャンクを無視して学習時の知識で答えてしまう、複数チャンクの内容を混同する |

## 落とし穴

1. **「検索さえ当たれば正解する」と思い込む**：正しいチャンクを渡しても、LLMがそれを無視したり誤読したりする生成側の失敗は別に検証が必要
2. **チャンクサイズを固定値のまま放置する**：文書の種類（表・箇条書き・長文の説明）によって最適なチャンクサイズは変わる
3. **検索精度と回答品質を同じ指標で測る**：検索が外れているのか、生成が誤っているのかを切り分けないと、どこを直すべきか判断できない

## 実務への接続

社内文書検索やFAQ対応にAIを組み込む場面では、まず「検索が正しいチャンクを上位に出せているか」を、生成結果とは別に確認する習慣が有効。回答が誤っていたときに、検索の失敗か生成の失敗かを切り分けられないと、改善の的が絞れない。

## 講座で使うなら

- 30 秒説明: 「AIに社内文書を全部覚えさせるのではなく、質問のたびに関連しそうな箇所を検索して見せてから答えさせる仕組みがRAGです」
- たとえ話: 一夜漬けで全部暗記させる（ファインチューニング）のではなく、試験中に必要なページだけ開いて良い「持ち込み可」の参考書（検索対象の文書）を渡すようなもの
- 演習案: 受講者に、自分の業務でAIに答えてほしい質問を1つ挙げてもらい、その答えの根拠になる社内文書がどこにあるか（あるいは無いか）を確認させる
