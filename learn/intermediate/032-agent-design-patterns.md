# 032 計画・実行・振り返り：エージェント設計パターン

!!! abstract "この記事で説明できるようになること"
    - エージェントの実装で繰り返し使われる代表的な設計パターンを 5 つ説明できる
    - 「計画→実行→振り返り」という発想が、どのパターンに対応するか見分けられる
    - 目の前のタスクにどのパターンが向くか、判断基準を持てる

## 仕組み

Anthropicの技術ブログ「Building Effective Agents」は、エージェント的なシステムの作り方を次の5パターンに整理している。

1. **Prompt Chaining（連鎖）**：タスクを一連のステップに分解し、各LLM呼び出しが前のステップの出力を処理する。精度は上がるがレイテンシも増える。
2. **Routing（振り分け）**：入力を分類し、専門化した後続処理に振り分ける。問い合わせ内容に応じて対応窓口を変えるイメージ。
3. **Parallelization（並列化）**：複数のLLM呼び出しを同時に走らせ、結果を集約する。独立した部分タスクを並列実行する「セクショニング」と、同じタスクを複数回実行して多数決を取る「投票」の2種類がある。
4. **Orchestrator-workers（司令塔と作業者）**：中央のLLMが動的にタスクを分解し、複数のワーカーLLMに委譲して結果を統合する。事前に手順を決め切れない、予測不可能な部分タスクが必要な場面に向く。
5. **Evaluator-optimizer（評価と改善）**：一方のLLMが応答を生成し、もう一方が評価・フィードバックを返す。生成→評価→改善のループを回し、応答の質が反復改善で伸びる場合に効く。

「計画→実行→振り返り」という発想は、この5つのうち **Orchestrator-workers（計画・委任）** と **Evaluator-optimizer（検証・改善のループ）** の組み合わせに最も近い。司令塔が計画を立ててタスクを振り分け（計画・実行）、生成物を評価者が検証して改善指示を出す（振り返り）という流れになる。

## 比較・判断基準

| パターン | 向いている場面 | 弱点 |
|---|---|---|
| Prompt Chaining | 手順が固定的で、各ステップの検証がしやすい | ステップ数に比例してレイテンシが増える |
| Routing | 入力の種類ごとに最適な処理が明確に分かれる | 分類ミスがそのまま誤処理につながる |
| Parallelization | 独立に処理できる部分タスクが多い、または多数決で精度を上げたい | 呼び出し回数分のコストがかかる |
| Orchestrator-workers | タスク分解の仕方を事前に決め切れない | 分解の質が中央LLMの能力に依存する |
| Evaluator-optimizer | 「良い応答」の基準を明確に言語化できる | 改善ループが長引くとコスト・時間が跳ね上がる |

## 落とし穴

1. **固定手順で十分なのにOrchestrator-workersを使う**：分解の仕方が毎回同じなら、Prompt Chainingで手順を固定した方が速く安定する。
2. **Evaluator-optimizerのループに終了条件がない**：「何回改善したら止めるか」を決めておかないと、コストとレイテンシが際限なく積み上がる。
3. **並列化した結果の集約方法を決めていない**：セクショニングも投票も、最後に結果をどう統合するかの設計をサボると、矛盾した出力を人間がまた手作業でまとめる羽目になる。

## 実務への接続

今日の現場ネタで紹介した「ECC」というエージェント・ハーネスは、「計画→テスト→実装→レビュー→検証→記憶→改善」という7段階のワークフローを構造化している。これは、司令塔役が計画を立ててサブタスクに分解する部分がOrchestrator-workers、レビュー・検証・改善を繰り返す部分がEvaluator-optimizerに相当する、2パターンの組み合わせと見ることができる。既存のエージェントツールを導入する際、「このツールはどのパターンの組み合わせで動いているか」を分解して理解しておくと、向いているタスクと向いていないタスクの見立てが立てやすい。

## 講座で使うなら

- 30 秒説明: 「エージェントの作り方には、手順を並べる／振り分ける／並列で走らせる／司令塔が計画する／評価者が改善させる、という5つの基本パターンがあります」
- たとえ話: 新人に仕事を教える方法にも、マニュアル通りにやらせる（連鎖）・案件ごとに担当を分ける（振り分け）・チームで一斉に手分けする（並列化）・リーダーがその場で仕事を割り振る（司令塔）・先輩がレビューして直させる（評価と改善）という複数のやり方があるのと同じ
- 演習案: 受講者が使っている（または使いたい）エージェントツール1つを選び、上の5パターンのどれに近いかを議論させる
